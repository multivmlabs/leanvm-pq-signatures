1. **Incorrect compressed-payload cap, fixed.** The former guest and Python verifier imposed a 625-byte payload limit. Pinned `crypto_sign_open` imposes no such limit: `nist.c:344` checks exact decoder consumption; the signer's separate buffer permits 647 payload bytes. For any challenge `c`, choose `s2=a*(1+X+...+X^511)` and `h=c*(1-X)/(2*a)` modulo `q` and `X^512+1`. Since `(1-X)*(1+...+X^511)=2`, this independently constructed key gives `s0=0` without using the witness NTT. The former guest rejected the valid 640-byte case below. Removed the invented length policy and its encoded-length accumulator, retaining coefficient and norm constraints. Evidence: `finding.json`, `independent_audit.py`, `tests/test_falcon.py:124`.

2. **Trailing zero bytes accepted by host decoder, fixed.** `decode_signature` checked that every remaining bit was zero without checking the consumed byte count. Appending one zero byte to KAT 0's 615-byte compressed payload preserved its decoded polynomial, while a correctly length-adjusted signed message was rejected by pinned C. The original KAT was the accepting control. `python/pqbench/falcon.py:88` now requires `ceil(consumed_bits/8)==len(encoded)` and still permits zero padding within the final byte. The fixture builder already ran complete upstream C verification before Python decoding; this disagreement did not bypass that guard or forge a guest proof. Evidence: `codec-finding.json`, `tests/test_falcon.py:70`.
